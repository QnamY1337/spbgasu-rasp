# Расписание СПбГАСУ

Android-приложение (Kotlin, Jetpack Compose) с расписанием пар СПбГАСУ, напоминаниями и отслеживанием замен.
Разработка идёт по фазам. Готово:

- **Фаза 1** — разведка источника и парсер расписания.
- **Фаза 2** — Room (пары, недели, замены, задания, экзамены), репозитории, DataStore, Hilt, use case'ы
  и поиск замен сравнением снепшотов.
- **Фаза 3** — онбординг (поиск группы по каталогу сайта, в том числе латиницей) и главный экран
  «Сегодня / Неделя» в официальных цветах СПбГАСУ, светлая и тёмная тема.
- **Фаза 4** — напоминания о парах (AlarmManager + WorkManager), восстановление после перезагрузки,
  экран настроек и нижняя навигация.
- **Фаза 5** — фоновая синхронизация, лента замен и уведомления об изменениях.
- **Фаза 6** — виджет «Ближайшая пара» на главный экран (Glance).
- **Фаза 7** — дорога до вуза: корпуса, адрес дома, время выхода, «Пора выходить», маршрут в Яндекс.Картах.
- **Главная** — стартовый экран: пары на сегодня, дорога к первой паре, место под погоду (фаза 10).
- **Фаза 8** — домашние задания: список со сроками, добавление из карточки пары, напоминания о дедлайнах.

## Сборка и тесты

Нужен JDK 17+ (подойдёт JBR из Android Studio) и Android SDK (compileSdk 37).

```bash
./gradlew :app:testDebugUnitTest            # тесты на сохранённых ответах сайта
./gradlew :app:testDebugUnitTest -Plive     # + живой запрос к rasp.spbgasu.ru
```

## Как устроен источник данных (разведка, 28.09.2026)

Эндпоинт `POST https://rasp.spbgasu.ru/bitrix/services/main/ajax.php?mode=class&c=gasu:raspisanie.csv&action=getRasp`.

Отличия от первоначальной спецификации, найденные на практике:

- **Нужен CSRF.** Без заголовка `X-Bitrix-Csrf-Token` и сессионной cookie `PHPSESSID` приходит `invalid_csrf`.
  Токен берётся с главной страницы (`'bitrix_sessid':'…'`). Если он протух, Bitrix присылает свежий в
  `errors[0].customData.csrf` — клиент повторяет запрос один раз.
- **Тело только form-urlencoded**: `search_params[SEARCH]=3-ТТП-26&search_params[FILTER]=GROUPS&…`.
  JSON-тело Bitrix не разбирает («Could not find value for parameter {search_params}»).
- **Частичный поиск не работает**: `SEARCH` должен точно совпадать с названием группы.
  Для автокомплита на главной странице есть полный список групп — `window.GROUPS = [...]` (614 групп).
- **Несуществующая группа** — это `status: success` с 8 пустыми неделями, а не ошибка.
- В одной паре может быть несколько аудиторий/преподавателей (подгруппы) через `<br>` или запятую:
  `421(1)/Г<br>421(2)/Г`. Аудитории бывают вида `406*/К`, `Актовый зал/Г`.
- Резервный `GET /getExcel.php?TYPE=GROUPS&FIND=…` отвечает `.xlsx` (application/vnd.ms-excel).

## Как ищутся замены

Сайт не отдаёт список замен, поэтому `SyncScheduleUseCase` при каждой синхронизации сравнивает свежее
расписание с сохранённым (`ScheduleDiffer`) по слотам «дата + номер пары»:

- первая синхронизация замен не даёт, прошедшие дни не сравниваются;
- сравниваются только недели, которые есть в обоих снепшотах: публикация новой недели — не «добавленные пары»;
- подгруппы в одном слоте сопоставляются сначала целиком, потом по предмету, потом по порядку —
  перестановка подгрупп на сайте замен не даёт;
- если сайт вдруг вернул пустое расписание, а раньше пары были, снепшот не перезаписывается.

Типы замен: `SUBJECT` (включая смену лекции на практику), `ROOM`, `TEACHER`, `CANCELLED`, `ADDED`.

## Структура

```
app/src/main/java/com/example/gasuschedule/
├── data/
│   ├── remote/      — BitrixScheduleSource (сессия, CSRF), ScheduleHtmlParser, MainPageParser
│   ├── local/       — Room: AppDatabase, сущности, dao/, prefs/ (DataStore)
│   └── repository/  — реализации репозиториев
├── domain/
│   ├── model/       — Lesson, ScheduleWeek, ScheduleChange, HomeworkItem, ExamEntry, ошибки
│   ├── repository/  — интерфейсы
│   └── usecase/     — SyncSchedule, ScheduleDiffer, GetTodaySchedule, GetWeekSchedule
└── di/              — Hilt: NetworkModule, DatabaseModule, RepositoryModule
```

Схема БД экспортируется в `app/schemas/` — при изменении сущностей нужна миграция и новая версия БД.

Тесты Room идут на Robolectric: образ Android скачивает Gradle в `~/.gradle/robolectric-jars`
(встроенный загрузчик Robolectric здесь падал на SSL, а из пути с пробелами не грузится нативная библиотека).

## Дизайн

Официальная палитра СПбГАСУ из макета: шапка `#96331A`, акцент `#C14524`, фон `#F3F3F4`.
Шрифты — IBM Plex Sans и IBM Plex Mono (время, номера пар), лицензия SIL OFL 1.1 — `third_party/IBM-Plex-OFL.txt`.
Тёмная тема в макете не нарисована и выведена из тех же оттенков. Dynamic color не используется,
чтобы не подменять фирменные цвета цветами обоев.

## Напоминания о парах

- `ScheduleNotificationsUseCase` считает напоминания на сегодня и завтра (запас на случай, если
  ежедневный пересчёт опоздает) и ставит их через `AlarmReminderScheduler`.
- Пересчёт: WorkManager ежедневно около 00:05, после каждой синхронизации, при смене настроек,
  после перезагрузки, обновления приложения, смены времени или часового пояса (`SystemEventsReceiver`).
- Будильники точные (`setExactAndAllowWhileIdle`) благодаря `USE_EXACT_ALARM`. Без него Android 14+
  вправе задержать обычный будильник до часа. Если точные всё же запрещены — окно ±5 минут.
  **При публикации в Google Play** использование `USE_EXACT_ALARM` нужно будет обосновать.
- Время пар всегда московское (`ScheduleTime.ZONE`), независимо от часового пояса телефона.

## Замены

- `SyncWorker` (WorkManager) запускается каждые 3 часа при наличии сети. Днём (7–23 ч) идёт на сайт,
  если с прошлой сверки прошло больше 2 часов, ночью — не чаще раза в 8 часов (`BackgroundSyncPolicy`).
- Найденные замены сохраняются в историю; уведомление одно на все непросмотренные (заменяет прежнее),
  по тапу открывается «Расписание» на вкладке «Замены». Бейдж с числом непросмотренных — на «Расписании»
  в нижней панели и на вкладке «Замены».
- В debug-сборке в настройках есть «Отладка: фоновая сверка сейчас» — тот же воркер без ограничения
  по времени, чтобы проверить уведомление о заменах.

## Виджет

- `NextLessonWidget` (Glance) показывает текущую или ближайшую пару из локальной базы, без сети:
  «ИДЁТ СЕЙЧАС · до 12:15», «БЛИЖАЙШАЯ ПАРА», «ЗАВТРА», «СР 30.09».
- Обновляется сразу после синхронизации, точно на границе пары (`WidgetRefresher` ставит
  отложенную задачу WorkManager) и раз в 30 минут силами системы как подстраховка.
- В настройках — кнопка «Добавить» (системный запрос на закрепление виджета).
- Плашка внизу: «Выйти в 08:15» для первой пары дня (если указан дом), иначе номер и время пары.

## Дорога до вуза

- Корпуса (`Buildings`): Г, С, А (2-я Красноармейская, 4), 5, Е, К, Б, Ф, УБ. Адреса сверены с картой
  map.spbgasu.ru, коды — со списком аудиторий сайта, координаты — OpenStreetMap.
  Корпуса на ул. Розенштейна из исходной спецификации на карте кампуса нет.
- Адрес дома — поиск через бесплатный геокодер OpenStreetMap (Nominatim, сначала Петербург с
  пригородами) или кнопка «Я дома» (системная геолокация, без Google Play Services).
- Время в пути — **оценка по расстоянию** (`TravelTime`), без платных API: пешком ×1,3 к прямой при
  4,5 км/ч; транспорт — 10 мин + ×1,4 при 20 км/ч, но не дольше, чем пешком; округление вверх до 5 мин.
  Router API Яндекса платный (от 195 000 ₽/год), поэтому от него отказались; точное время — в
  Яндекс.Картах по кнопке «Маршрут» в карточке пары.
- Время выхода = начало первой пары дня − дорога − запас (по умолчанию 10 мин): в карточке пары,
  плашке виджета и уведомлении «Пора выходить».

## Домашние задания

- Вкладка «Задания»: группы «Горят» (просрочено, сегодня, завтра), «На этой неделе», «Позже»,
  «Без срока», «Выполненные»; бейдж горящих на вкладке и строка на главной.
- Из карточки пары: срок по умолчанию — следующая пара по этому предмету (из расписания).
- Дедлайн — начало пары по предмету в день сдачи, иначе 09:00. Напоминание за N часов
  (настройка «Дедлайны заданий», по умолчанию 12 ч).

Вкладка «Сессия» в «Расписании» пока показывает только пояснение: расписание сессии не опубликовано.
Разведка 28.09.2026:
- Расписание сессии на сайте — https://rasp.spbgasu.ru/sessia (страница «Расписание промежуточной
  аттестации» на spbgasu.ru ведёт туда). Это тот же сайт: `window.ONLY_SESSIA = "Y"`, тот же список групп.
- Данные — тем же запросом `getRasp`, только `search_params[ONLY_SESSIA]=Y`.
- Сейчас ни у одной из ~30 проверенных групп (очные, заочные, старшие курсы) сессия не опубликована:
  ответ — пустые недели, как для несуществующей группы. Реальной разметки экзаменов пока нет.
- Ссылка из спецификации (spbgasu.ru/Studentam/.../Raspisanie_ekzamenacionnoy_sessii/) — 404.

Когда сессия появится: сохранить реальный ответ как фикстуру, проверить, подходит ли `ScheduleHtmlParser`
(и какие там метки типа — «экз.», «зач.», «конс.»?), затем экран с обратным отсчётом.
